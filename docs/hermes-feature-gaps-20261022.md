# Hermes 功能差异与补齐清单

检查日期：2026-10-22。对照当前工作区（包含本次认证与连接整理）和
`nesquena/hermes-webui` 的 `e68f38327948ba5c480ae2a258881aa00497c1cf`。

本清单基于入口、组件调用、请求和适配器的源码检查，不代表两套应用
所有功能都经过真实 Hermes 服务、真实模型或手机实测。参考项目的路线图
仅作为索引；关键差异核对了实际实现。未给功能覆盖率估算。

## 本轮实施进展

已完成并接入现有界面：Hermes 专属命令菜单（compact/name/session/copy）、
官方全文搜索及归档/未加载会话结果、匹配消息定位、聊天普通文件选择和拖入、
项目目录确认、上传进度、失败重试及同名文件保护。

验证入口：`npm run test:hermes` 和 `e2e/hermes-chat-essentials.mjs`。
浏览器验证使用真实临时文件上传与模拟 Hermes 响应；本机配置的后端搜索
探测返回 502，因此未将其计为真实部署或真实模型验收。

下方表格保留首次审查的状态与证据；尚未实施消息编辑/重新生成/分支、
会话导出及后续批次。当前命令列表会明确拒绝尚未实现的命令。

## 已有能力

以下能力不应重复立项：

- 普通聊天、项目目录聊天、模型与推理级别选择。
- 工具调用与推理内容显示、停止、审批、澄清、刷新后的运行恢复。
- 会话重命名、删除、置顶、归档、分页加载、完整历史和手动压缩。
- 项目目录选择与恢复、文件浏览/搜索/上传/下载、预览和本机终端。
- Cron 创建、编辑、暂停、恢复、手动运行和运行记录。
- 技能查看/编辑/启停、技能市场、MCP、渠道接入、插件、Webhooks、配对。
- 配置档案创建/复制/编辑/默认选择/导入导出；导入当前要求服务器归档路径。
- 记忆编辑、模型供应商和密钥配置、用量统计、日志。
- 子任务状态、查看输出、停止和补充指令。此项不等于主会话 steering。
- 产物浏览、下载和版本保存。
- 密码/Nous 登录、服务端会话撤销和三条后端链路诊断。
- 浅深色主题、移动布局、PWA 注册和离线页面基础设施。

主要入口：`HermesChat`、`HermesSettingsDialog`、`HermesWorkspacePage`、
`HermesAdvancedModules`、`HermesManagement` 和 `HermesRightPanel`。
旧 Pi API 或组件仍在仓库，不代表 Hermes 页面已经接入其功能。

## 第一批：高频操作和入口一致性

| 功能 | 当前项目证据 | 对方实现证据 | 建议与验收 |
| --- | --- | --- | --- |
| Hermes 命令菜单 | `ChatInput.tsx` 的内置列表仍包括 Pi 的 compact/auto-compact/reload/name/session/copy/clone；`HermesChat` 未传 `onBuiltinCommand`、动态命令加载等回调；请求按文本送给后端 | `static/messages.js` 与 `static/commands.js` 有 Web/Agent 命令分类和处理 | 先识别当前后端支持的命令；本地 UI 命令明确分发，原生命令按真实协议执行，不支持项不展示。不能把普通文本请求当作命令执行成功。 |
| 全局会话搜索 | `HermesSidebar.tsx` 只过滤传入的 sessions 的标题、preview、cwd；首次列表为 50 条，需要手动加载更多 | `static/sessions.js` 实际请求 `/api/sessions/search?...&content=1` 并合并结果 | 搜索所有会话及正文，展示匹配片段，点击定位消息；包含未加载和归档记录，取消旧请求并处理分页。 |
| 编辑、重新生成、分支 | `MessageView` 有可选编辑/分支接口，但 Hermes 调用未传 entryId/onFork/onEditContent；消息适配器未保留这些操作所需的稳定消息标识 | `static/messages.js` 的 regeneration；`ROADMAP.md` 的 conversation controls 和对应 session handlers | 先核对官方消息标识和分支契约，再支持修改上一条、重试/重新生成、从某条消息开分支。保留原会话和模型/目录/档案归属，避免重跑工具副作用。 |
| 聊天普通文件附件 | 侧栏 `FileExplorer` 能上传；聊天 `ChatInput` 没有 `onAttachFiles`，其文件选择器回退为 `image/*`；未接入 `useDragDrop` | 对方 `static/messages.js` 的 pendingFiles 和上传流程 | 复用既有上传服务和目录确认，支持选择/拖入普通文件、进度、冲突和失败保留。先交付文本/代码文件；PDF/Office 需要核实提取能力，不能只上传就声称已理解文档。 |
| 会话导出与备份 | 会话菜单只有既有重命名/置顶/归档/删除等操作；产物下载与配置档案导出并非会话导出 | `static/sessions.js` 的分享/导出菜单；参考 README 的 Markdown/JSON 导入导出 | 先交付私有 Markdown/JSON 下载和可验证的导入，再考虑只读分享。分享应采用显式快照、脱敏、过期和撤销，不能直接放开整个会话 API。 |

第一批建议顺序：命令菜单一致性 -> 全局搜索 -> 聊天文件附件 ->
消息编辑/重新生成/分支 -> 私有会话导出。消息操作与导入导出需要先确认
当前 Hermes 后端能力，不能直接调用参考项目自己的 Python 路由。

## 第二批：运行控制和工作区完整性

| 功能 | 当前状态 | 补齐方向 |
| --- | --- | --- |
| 主会话 Queue/Steer/Interrupt | `send` 在 busy 时拒绝；ChatInput 未接入 `onSteer`/`onFollowUp`。子任务控制已有，主会话未接入 | 用户可以在运行中补充要求、排队下一条、停止后修改；服务端确认接受后再清输入，恢复不能重复投递。参考 `static/messages.js` 的 busy-mode routing。 |
| 后台多会话运行 | `openSession` 在运行中直接返回，侧栏选择/新建受 busy 限制；浏览器仅保存一个 active-run 记录 | 按 session/run 建立运行集合；切换仅解除观察，不停止任务；侧栏展示运行/等待审批/失败/完成，支持回到原会话。先让单任务后台运行可切换，再考虑并发。 |
| 完成、失败、审批提醒 | Pi 的 `AppShell` 有通知与音效代码；Hermes 页面没有接入相应生命周期 | 优先页内未读和状态标识，再加可选声音、后台浏览器通知；任务完成、失败、审批分别处理并去重。关闭页面后的可靠提醒需要独立后端投递，不能等同于前台 Notification。 |
| 文件编辑和基本操作 | 当前 FileViewer 主要读取/预览/diff/下载；文件 API POST 处理上传、冲突预检和链接授权，没有专用保存/重命名/删除流程 | 在现有右侧面板增加编辑/保存、新建、重命名；破坏性操作确认，保存前冲突检查，目录允许列表仍为边界。参考项目 `api/routes.py` 有独立文件操作路由。 |
| 项目组织 | 当前有真实 cwd、最近目录、草稿和分支信息，没有命名会话分组/标签/批量整理 | 增加轻量项目分组与筛选，再绑定默认目录/模型；明确“会话分组”和“文件目录”的区别。保留现有侧栏风格。 |
| 每会话配置档案 | 当前管理的是默认档案，UI 明确说明运行服务和已有会话保持原方案；聊天创建未传 profile | 只有后端支持会话级绑定后才新增选择器；创建会话时保存归属，后续模型/记忆/技能/目录都按该归属路由。不能把更改启动默认档案包装成会话切换。 |
| 上下文与任务进度 | 已有累计 token/费用、完整历史和压缩；没有可确认的当前上下文占用和主会话 Todo 专用视图 | 使用原生上下文统计和 Todo 事件，缺数据时显示未知；累计调用用量不能冒充上下文百分比。Todo 工具卡不等于持续更新的任务列表。 |

这些能力涉及会话归属与运行生命周期。应先延伸统一聊天客户端和
服务端运行存储，再接界面，不应在页面中重新增加多套协议分支。

## 第三批：部署与可选体验

- 首次使用向导：将现有连接诊断、模型选择、目录选择和只读检查串成流程。
  对方有 `api/onboarding.py` 和 `static/onboarding.js`；我们目前是分散设置入口。
- 语音：目前语音设置管理的是 Hermes 工具能力，不等于网页麦克风输入或
  回复朗读。对方 `static/boot.js` 有真实录音/识别及降级逻辑。
- 登录：我们已有密码和 Nous；对方还支持通用 OIDC、Passkey 和受信代理身份。
  个人实例优先完成现有登录稳定性，团队部署再考虑通用 SSO。多种登录方式
  不等于数据、工具权限和 OS 账号的多租户隔离。
- 用量分析：我们已有汇总、按模型和每日表格；可补时间范围、趋势和技能用量，
  不应将整个统计模块列为缺失。
- 历史阅读：已有完整历史按钮。后续可从一次全量读取改为向上按页加载，
  并保留滚动位置和搜索定位；这属于性能与交互增强。
- PWA：已有注册和离线基础。可核查应用名称残留和升级提示，完善移动端
  附件与长任务恢复；无需重做一套 App 外壳。
- 主题皮肤、原生客户端和参考项目独有的 UI 扩展生态不作为当前优先项。
  保持当前视觉系统；Hermes 插件管理与 WebUI 自身扩展不是同一个能力。

## 实施约束

1. 保留当前 React 组件、布局、主题和移动交互，只在原有位置补齐控件。
2. 功能必须走真实 Hermes 合同；参考项目自身的 `/api/...` 并不天然存在于
   我们连接的官方 Dashboard/API Server。新增前验证安装版本与能力。
3. 操作消息需要稳定的持久标识，不能用显示数组下标或运行时 session ID
   代替消息/会话标识。分支、恢复和导出应保持工具调用与结果配对。
4. 每批分别记录源码/单元测试、浏览器模拟回归、真实后端和真实模型证据。
   本次功能审查未执行真实模型、修改配置、发送渠道消息或进行部署。

# Settings panels: plugins, skills and shared blocks

- Read [the UI rulebook](../../DESIGN.md) before layout changes. Reuse the `ConfigDetailHeader` / `ConfigDetailHeaderInfo` / `ConfigDetailActions` pattern for a title on the left and the primary action on the right. Secondary actions use `.hermes-detail-toolbar`; destructive actions stay separate. Editing uses the existing right-aligned `ConfigFooter`. Shared control dimensions live on `.hermes-layout`; mixed module action bars align as a group to the right.

- HermesActivityRail adds five workspace destinations without replacing settings navigation. HermesWorkspacePage reuses the same scoped management components; workspace tab/rail changes guard dirty drafts. Keep the home chat, session sidebar and right panel mounted while hidden so runs, input drafts and terminals survive navigation. Opening settings returns to home after the existing discard guard. The rail is inert while a settings modal is open.
- The bottom user icon opens HermesAccountMenu using the shared SidebarMenu (desktop popover/mobile sheet), never jumps directly into settings. It reads authentication on open, shows official/password/unprotected/signed-out states, exposes sign-in or sign-out through the existing web-auth flow, and embeds HermesAccountSettings for authentication/backend connection details. Default profile choices use POST /api/profiles/active {name}: this changes the sticky launch default only; show the separate current service profile and never claim a running dashboard/session was retargeted. Manage profiles explicitly opens the existing editor through its dirty-state guard. Error/retry, Escape/outside dismissal and focus return remain shared menu behavior. Verify e2e/hermes-account-menu.mjs; account/profile responses and logout are mocked to avoid touching a personal login.
- HermesArtifacts uses a compact header, inline type tabs, session dropdown (all sessions by default), lazy media cards and a native preview dialog. The server-side artifact index and security boundary are documented in sessions.md. Markdown files/code blocks default to rendered preview with source toggle; text files stream through the authenticated managed-file endpoint with a 1 MiB client limit. ReactMarkdown never enables raw HTML; document assets use Hermes file URLs, never Pi file-root grants. HTML/SVG code previews use an opaque sandbox with scripts disabled and a restrictive CSP. Workspace files reuse FileExplorer/FileViewer and the existing directory validation/access boundary.
- MCP keeps server and official catalog lists in separate modes, searchable by name. List rows have stable heights and a status icon with an accessible label; details use a bounded vertical form and sticky action footer. MCP authentication, partial updates, profile scoping and draft protection are identical in workspace and settings views.
- Channels and MCP use HermesResourceState for initial loading and failed reads, with an explicit retry and expandable diagnostics. Failed requests must not appear as empty lists or selection instructions. MCP keeps unsaved editors visible on refresh failure.

## Hermes management adapter
- The Hermes homepage uses `components/HermesManagement.tsx`, sharing `SettingsUi` blocks and the Pi Web CSS variables. It never sends Hermes management operations to the original Pi `/api/skills`, `/api/models` or settings routes.
- Browser requests go through `lib/hermes-client.ts` and `/api/hermes/**`; the active route imports `lib/hermes-api-proxy.mjs`. The neighboring TypeScript proxy is not the route's runtime implementation.
- Official contracts: Cron lists are arrays, update is `PUT /api/cron/jobs/{id}` with `{ updates }`, actions use POST pause/resume/trigger. Preserve the owning job's profile on every operation. Schedule display text is not necessarily valid input: cron uses `expr`, interval uses `minutes`, one-shot uses `run_at`.
- Cron has its own `hermes-cron` layout: search/add/refresh stay in the task sidebar; rows have automatic height with a 92px minimum, a two-line name and separate schedule/state/profile lines. Never inherit the shared 30px settings-row height for these multi-line items. Detail uses a bounded reading column, top actions, schedule/next-run/result summary and Markdown prompt; the editor groups basic fields, prompt and collapsible advanced options with a sticky save/cancel footer. Preserve advanced values and profile-scoped payloads; failed saves retain inputs and switching tasks guards the open form. Below a 720px container width, show either the list or the detail/editor, with Back to tasks preserving the form; this applies inside Settings too. Verify e2e/hermes-cron-layout.mjs and the Cron workflow in e2e/hermes-workspace.mjs (fixture mutations only).
- Skills uses an array list, `{ name, enabled }` toggle, `{ name, content }` create/update and `GET /api/skills/content?name=`. Config raw is `{ yaml, path }` on GET and `{ yaml_text }` on PUT. Keys is a map of redacted records; PUT is `{ key, value }`, DELETE also requires a JSON `{ key }` body. Never prefill a key editor with its redacted preview.
- Installed skills use HermesSkillList: search, create and refresh belong inside its list header, not a full-page toolbar. Use spacious rows, independent selection buttons and switches, and the official `/api/skills` `usage` field. Missing usage is unknown, never fabricated as zero. Default ordering is usage descending, with name/category options. Provenance `agent` includes handmade skills, so label it Local rather than Learned. Toggle only updates the requested skill and preserves the selected editor/draft. Keep the list/detail widths responsive in both workspace and settings.
- Skills Hub uses a responsive card grid with description, real source/category and installed status. Installation filters are local; search still uses the official search endpoint. Details replace the grid and provide a back button that restores card focus. Installation/check/uninstall stay in the detail footer; retain scan blocking and background exit-code verification. Link lookup is a collapsed secondary entry. Empty and failed reads must remain distinct.
- Skills Hub keeps search, source, catalog actions and the collapsed link entry in one wrapping toolbar. Desktop controls are 32px tall; the native source select retains keyboard support with a decorative Lucide chevron. Keep its header, toolbar and card grid aligned and avoid stacking a separate empty toolbar row. Settings uses a compact shared breadcrumb header.
- Mutations reload only after success; errors retain the entered value. Saved key inputs are cleared. Workspace navigation warns about dirty editors. Contract browser coverage lives in `e2e/hermes-workspace.mjs`, with upstream responses mocked; this is not evidence of live Hermes integration.

## General appearance
- `components/FontSettings.tsx` offers separate interface/chat and monospace (code, tool output, terminal) font-name lists in the Fonts & layout section after Appearance, together with chat font size and content width; the Chat section keeps only behavior switches. Every row there has one shape: a header line (label, value, reset button in a fixed 28px column) over a full-width slider, so values and resets line up. A font row puts its name field between label and value, and its slider is the weight (100–600, step 100; `aria-valuetext` adds the weight's name). Both font rows share one grid (`subgrid`), so their name fields start at the same x whatever the labels' widths in each locale. The name field is drawn in the font it names, which is the preview; keep one short section description, no separate preview lines or per-control paragraphs. `hooks/useFontPreferences.ts` stores them only in the browser (`pi-ui-font-family`, `pi-mono-font-family`), applies changes immediately through `--font-ui` / `--font-mono`, and syncs other tabs. AppShell keeps the hook mounted so restoring a font never requires opening Settings or a chat. Empty input removes the override; the original stacks stay in `app/globals.css` as `--font-ui-default` / `--font-mono-default`.
- Font names refer to fonts on the **browser's device**, not the server; no enumeration, upload or remote download. `lib/font-preferences.ts` treats commas as separators, accepts optional enclosing quotes, quotes non-generic names as data, and always appends the default stack. Never interpolate font input into a stylesheet or accept it as executable CSS. Keep raw input whitespace while typing so multi-word names remain editable.
- Each font has a separate base weight (100–600 in steps of 100, default Regular/400; it stops at 600 because headings and labels use 600 and bold text, highlighted bold and the terminal's bold use 700, so a heavier base would outweigh them), stored as `pi-ui-font-weight` / `pi-mono-font-weight` and applied through `--font-ui-weight` / `--font-mono-weight`. Missing/invalid stored weights use 400; saving 400 removes the override. Each reset clears that font's name **and** weight in one update, not the other font or chat size/width. The UI weight is inherited by ordinary interface/chat text; code/pre, highlighted code (including its inline theme styles), source-view line numbers and diffs use the mono weight. Headings, Markdown bold/inline code inside emphasis, and other explicitly weighted labels keep their original weights; do not blanket-override them with `!important`.
- General's Sidebar section (after Chat) chooses where the desktop sidebar shows the file browser: below the sessions (default) or in a tab of its own, as two options in the send key's look (`settings-send-mode-option`), with "Phones always use tabs." under them (`aria-describedby`; `.settings-chat-options + .settings-general-description` turns a section's introduction into a note under its options). `hooks/useFilesPlacement.ts` keeps it per browser (`pi-web:sidebar-files-placement`; anything but `tab` reads as `below`) through `useSyncExternalStore`, so the server and hydration render `below` and the stored choice follows; it follows another tab through `storage` events and reads the key again when a first consumer subscribes, since nobody listened meanwhile. A blocked storage still applies the choice for the page. `SessionSidebar` reads it too and switches live, without remounting the explorer or the tree (sessions.md, the toolbar row and the two layouts); on a phone the choice is kept but the tabs show.
- ChatInput remeasures an existing draft when the interface font or weight changes. TerminalPanel subscribes in its existing lifetime effect, updates xterm's family and normal weight (its bold stays xterm's default 700, above every base weight) and refits, never restarting the terminal or its SSE stream for a font change.

## Plugins and skills
- `/api/plugins` uses pi's `SettingsManager` + `DefaultPackageManager` for global/project package install, remove, update, enable and disable; disabling writes empty `extensions/skills/prompts/themes` arrays to the package entry.
- `/api/skills` lists through `DefaultResourceLoader`, so settings paths, package skills and project `.agents/skills` appear as the runtime sees them. The detail pane lazily reads a selected skill through `/api/skills/content` and renders its post-frontmatter instructions as Markdown; that route permits only an exact file path returned by the same runtime loader and caps the regular-file read at 1 MiB, rather than becoming a general Markdown-file reader. Toggling a skill edits only the `disable-model-invocation` frontmatter key of its `SKILL.md`, so user formatting survives, and `PATCH /api/skills` edits only `.md` files (its roots also hold `auth.json`, settings and project files). `/api/skills/install` shells through `npx skills add ... --agent pi`; project installs run in the selected cwd.
- **Group switches.** Each sidebar group of the Skills, Plugins and MCP panels (a skill scope, a package scope, an `mcp.json`; not standalone extensions) has a `ConfigSidebarGroupSwitch` in its heading row, so the 190px phone sidebar loses no height. As with the Models provider switch, it is on only while every row is: a partial group reads as off beside its `n/m` count and one click completes it. A panel whose group can hold rows its switch never turns on passes its own `checked` (MCP: `mcpGroupSwitchChecked()`), or the switch stays off for good. One request carries the list (`PATCH /api/skills` `filePaths`, `POST /api/plugins` `packages`, `POST /api/mcp` `set-enabled` `servers`) and answers per item, so a refused row does not stop the rest; what was left undone shows under the heading (`ConfigSidebarGroupStatus`). An entry already in the requested state is left alone; enabling keeps an entry's own keys such as `autoload`. `SettingsManager` never throws a failed load or write (`flush()` resolves), so the bulk plugin path reads `drainErrors()`, or an unreadable settings.json would report success. Disabling empties the four resource lists and keeps no filters, so a group switched off leaves an enabled filtered package on (the SDK reports every object entry as `filtered`) and says so; the bulk route refuses it.

## Shared blocks
- Hermes web forms filter other clients' `desktop`, `bot_desktop`, `display`, `voice` interaction preferences, terminal font and application updater fields through `isWebConfigField`; raw YAML remains complete. STT/TTS provider settings remain available for Hermes tools. `isConfigFieldApplicable` reveals only the selected terminal backend's image and selected STT/TTS provider's fields, without deleting hidden draft values. Advanced forms exclude categories already provided by dedicated pages; search uses the same scope. Settings section icons use an exhaustive typed Lucide map and group icons remain stable while filtering.
- Panels are built from the shared blocks in `components/SettingsUi.tsx` (`ConfigScopeTag`, `ConfigScopeSwitch`, `ConfigSaveTarget`, `ConfigAddSourceHeading`, `ConfigAddSourcePanel`, `ConfigDetailGrid`, `ConfigFooterStatus`, `ConfigTrustNotice`), `itemsToSwitch()` in `components/settings-ui-helpers.ts`, and `lib/display-path.ts`; a new settings section reuses them instead of copying a panel. `SettingsUi.tsx` takes every word as a prop and holds no state, so it renders outside the i18n provider; panels pass `t()` strings.
- **Every add pane chooses global or project in one place:** a `ConfigSaveTarget` (scope switch aria-labelled `config.saveTo`, plus the path that choice writes to) first under the pane's title, where a detail pane shows its `ConfigScopeTag` and path. Skills, Plugins and MCP get it through `ConfigAddSourceHeading` (title, the catalog links at its right, then the save target); Sub-agents put it in the detail header in place of the tag while creating. The submit button stays where its flow needs it (Install under the source box or on each skill result, Save in the footer, Add at the end of the MCP form), with why it waits beside it, not under the save target. The path is shown whole, never cut short: it wraps after a separator (`<wbr>`), then anywhere. Sub-agents offer both scopes whatever the folder's trust: profiles are not project resources that wait for it.
- **Why a control is unavailable is visible text** — a scope switch's `disabledReason` (under the switch's whole line, so controls passed as its `children` stay level with it), the note under a detail header, a footer summary that opens its diagnostics — never only a `title` tooltip, which a touch screen cannot show.
- `ConfigTrustNotice` shows its button only when given `onTrust`; Settings › MCP passes AppShell's trust dialog through `SettingsPanel` (see **Trust from Settings** in [mcp-settings.md](mcp-settings.md)). Skills and Plugins take the page's `trust` and reload after a decision but have no Trust button; adding one needs `onOpenTrustDialog` passed to them and `mcpProjectTrustable()`'s rule.

- HermesSettingsDialog retains the original modal surface and SettingsUi controls, with the user-requested left category menu and right content pane. Menu labels and standard status/usage labels are Chinese; wire names are not translated. Categories are searchable. On phones the category menu opens as an in-dialog drawer, taking focus and restoring it on close. Modal Escape/focus uses stacked-dialog helpers, with a Tab loop and dirty-state navigation guard. Models/Skills/Settings entry points stay at the bottom of the workspace sidebar; Settings opens General. General uses Pi theme, chat appearance, enter-send-mode and FontSettings preferences.
- HermesConfigEditor loads schema, normalized config and raw YAML in parallel. The YAML document is the shared draft for form and source modes. Form saves use `/api/config` with `{config: partialPatch}`; source edits/imports use `/api/config/raw` with `{yaml_text}`. Preserve comments, unknown fields, provider routing, boolean/number/list/object types and explicit nulls. Standalone category pages restrict search to their categories. Never write unrelated defaults merely by opening an editor.
- HermesModelsConfig uses the official custom-endpoints save API and `/{id}/activate` for default selection. Model enumeration uses the server-side adapter `/api/providers/custom-endpoints/discover`: GET model lists only, never an inference/transport probe. Normalize pasted API route suffixes, try the `/v1` alternate after an empty/HTML root or a missing path, and preserve canonical model metadata. For saved endpoints, resolve credentials through authenticated Dashboard reads on the server; never return secrets or forward a saved credential to an edited destination. Blank secret on edit means omitted `api_key`; never send the masked preview. Discovery errors are localized inline beside the model field and clear on edits/retry. Saving without `make_default` must not change the current conversation model.
- Hermes provider addition opens HermesProviderPicker above Settings, using the Pi card-grid layout, search and stacked-dialog Escape/focus handling. Catalogs come from `/api/model/options?include_unconfigured=1` and `/api/providers/oauth`; show only supported Hermes flows. Custom selects the endpoint editor; native providers use HermesBuiltinProviderConfig. API keys are saved separately through `/api/env`, default model changes explicitly through `/api/model/set` (honor expensive-model confirmation). Device-code login starts only on click and polls with cleanup; external login displays the official CLI command without executing it. Both custom endpoint switches have visible titles and descriptions, not just accessible labels.
- Chinese display strings live in `lib/i18n/hermes/ui.json`, with English copy in `ui-en.json`; use `useHermesI18n().ht()` and interpolation parameters. Refresh the catalog with `node bin/localize-hermes-ui.mjs`; do not rerun `--migrate` on already migrated components. Field copy is a static AST import from Hermes Desktop, with its MIT notice alongside `fields.json`. The form omits raw key names, field counts, paths and untranslated explanations. YAML source keeps technical information. Language choices persist separately from Pi under `hermes-web-locale`.
- `e2e/hermes-workspace.mjs` uses fixtures; `e2e/hermes-live-settings.mjs` performs read-only checks against the configured Dashboard. Only the latter proves live settings/schema connectivity, neither proves a real chat run.
- Profile management has one entry at the bottom of HermesActivityRail, below Settings; it is not repeated in the settings category menu or module toolbars. Skills Hub, Channels and MCP use the current-service scope (omit `profile`); memory resolves that same service's `current` profile. Preserve the scoped adapter APIs for explicit callers. Profiles changes the global default only via its explicit button; never silently change a running service or conversation's profile. Navigation to profile management keeps the existing dirty-draft guard. Skills Hub uses official/search/preview/scan and install/uninstall/update routes; scan policy `block` disables installation. CLI operations are successful only after action pid matches and exit_code is 0 (unknown, failed, superseded and timed-out actions are errors).
- Channel forms never prefill masked credentials. Only edited nonempty env values and explicitly marked clear_env keys are submitted. Existing allowlists use the backend's unmasked `value`. Show gateway reload requirements without automatically starting adapters or sending messages. MCP creates use the validated dedicated API; edits preserve the existing transport and patch only selected connection fields through the official config deep merge, retaining credentials, headers, other servers and unknown options. Plugin-owned servers are read-only; tests and OAuth are explicit actions. Cancel an unsettled OAuth flow when leaving its component.
- `e2e/hermes-advanced.mjs` verifies mutation flows using fixtures (including OAuth). `e2e/hermes-live-advanced.mjs` verifies live API writes only in a uniquely named temporary profile: create/edit/rename, scoped channel config, MCP add/enable/partial patch, and a local official skill install. It deletes the temporary profile in finally, and never activates it, connects messaging adapters, or changes existing profile data. Do not take screenshots of personal data; visual QA uses fixtures. Archive import/export currently use file paths on the Hermes host. e2e/run.mjs discovers fixture suites and excludes every live suite by default.

- Plugins, Pairing, Webhooks and Agents are HermesAdvancedModules sections in the settings sidebar, each with a distinct Lucide icon. Plugins use the authenticated allow-listed /api/hermes-control RPC bridge, never Pi package management. Plugin list/toggle is compatible with older backends; install/update/remove/settings depend on the actual Hermes version. Pairing grants by request_id, never a guessed code. Webhook secrets are shown once on creation and never persisted client-side. Native subagent requests use the original project run's RPC connection and inject its runtime session id; never rebind a live session to a management socket. Global delegation pause blocks new spawns, not existing children.
- HermesChannelOnboarding uses official Telegram/WhatsApp start/status/apply/delete APIs with one fixed scope. QR encoding is local and lazy-loaded; no third-party QR service sees the payload. Polling stops at readiness, expiry, failure or unmount. Cancel pending setup on unmount; a late start response must also be cancelled. Active setup participates in the dirty-navigation guard. Apply uses official restart results and never invents a connected state. e2e/hermes-completion.mjs exercises fixture mutations and chat recovery.

- Functional category navigation expands inside the single left settings sidebar; the top breadcrumb is static and has no dropdown; HermesConfigEditor has no inner category sidebar. The parent owns the selected category and the editor reports available schema categories. This does not remove operating lists: Skills, scheduled tasks and model providers still use their list sidebar. Form rows align labels/descriptions on the left and bounded controls on the right, with no technical metadata.
- HermesMemoryContent shows independent Markdown cards for notes, user profile and SOUL. Profile paths come from official `/api/profiles` metadata. Notes/profile use `/api/fs/read-text` and `/api/fs/write-text`; SOUL uses `/api/profiles/{name}/soul`. Treat only 404 as missing; never edit truncated/binary/failed reads. Re-read before each save and retain the draft if the original changed. The backend does not offer atomic compare-and-swap, so this is a preflight conflict check. Refresh/profile switching are disabled while dirty or saving. Avoid logging or snapshotting real personal file contents during QA; live checks are read-only and screenshots use fixtures.

- Hermes preferences are separate General, Theme, Fonts & sizes, and Chat display pages. FontSettings's original 100-step weight slider is not used by Hermes; its dedicated page offers pixel size controls and safe family-name fields. Initialize font families and Hermes size preferences in HermesWorkspace so refresh applies them before opening Settings. Theme skeletons use the real data-theme variables. UI labels scale with --hermes-ui-font-offset; chat size keeps the existing Pi appearance store; code size is separate. Native terminal font size is not changed by the code-block size control.
- Common runtime fields are curated in lib/hermes-settings-fields.ts rather than blindly trusting broad schema categories. Only verified translated field copy appears in forms; full YAML remains accessible. Do not submit hidden fields or default values when changing one visible control. Prefer server enum options; local enum overrides require evidence in installed Hermes source.
- Chat display preferences are browser-local. Preserve real reasoning_content / thinking blocks in history and reasoning.available event text, separate from the final reply. Never manufacture reasoning or issue Pi thinking-entry requests for Hermes history. Display toggles should not reload history or cancel a running stream.

- Channels uses a searchable runtime platform list with status dots and four state filters; filters leave the selected draft intact. The bounded detail column groups required credentials, access lists, optional settings and collapsed advanced fields. Clear buttons mark removals with undo until save; enable/test/save controls stay in the fixed footer. Mobile uses a horizontally scrolling platform list and an independently scrolling form. Fixture QA covers filters, search, advanced disclosure and clear undo without touching personal data.
